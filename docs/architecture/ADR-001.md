# ADR-001: Modular Python web application

Date: 2026-11-05. Decision by implementation team under delegated authority.

Use Python 3.12+, FastAPI, Uvicorn, SQLite and same-origin HTML/CSS/JavaScript.
Choose a modular monolith to keep policy and transaction boundaries explicit.
SQLite supports a single-instance development release; multiple deployment replicas require a PostgreSQL migration and concurrency validation before release.

Alternatives: TypeScript full stack offers shared types but requires a fresh dependency installation in the currently disconnected environment. A generic browser-agent-first architecture has excessive uncertainty and cannot establish provider automation permission. Both remain possible future decisions.

First increment uses clearly labeled synthetic sandbox opportunities and local transactional registrations. It does not fetch live offers, run an LLM, send messages or register with external providers. These capabilities need independently verified adapters and credentials. LLM outputs will never authorize execution. Approval binds application version and payload, with policy rechecked immediately before execution.

The selected cloud workspace is already isolated. Work on existing branch `work`; no additional worktree required. Preserve existing research documents.

Production release requires realistic browser E2E, durable deployment/restore tests, approved provider adapters, live source verification, credential management, security review and operational monitoring. Local test success cannot establish those claims.
